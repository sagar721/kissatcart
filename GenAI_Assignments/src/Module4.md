# Q1. Build a Student Grade Calculator with Codex

**Prompt given to Codex:**

> Create a Python console program `grade_calculator.py` called "Student Grade Calculator". It should:
> 1. Accept marks for 5 subjects (Maths, Physics, Chemistry, English, Computer).
> 2. Calculate total, average and percentage.
> 3. Show PASS if every subject is 40 or more, otherwise FAIL.
> 4. Reject marks below 0 or above 100, and non-numeric input, and ask again.
> Keep the code simple with small functions and comments.

**Code generated by Codex (`grade_calculator.py`):**

```python
SUBJECTS = ["Maths", "Physics", "Chemistry", "English", "Computer"]
PASS_MARK = 40


def get_mark(subject):
    while True:
        text = input(f"Enter marks for {subject} (0-100): ")
        try:
            mark = float(text)
        except ValueError:
            print("  Invalid input. Please enter a number.")
            continue
        if mark < 0 or mark > 100:
            print("  Invalid marks. Marks must be between 0 and 100.")
            continue
        return mark


def calculate(marks):
    total = sum(marks)
    average = total / len(marks)
    percentage = total / (len(marks) * 100) * 100
    passed = all(m >= PASS_MARK for m in marks)
    return total, average, percentage, passed


def main():
    print("=== Student Grade Calculator ===")
    marks = [get_mark(s) for s in SUBJECTS]
    total, average, percentage, passed = calculate(marks)
    print(f"Total Marks : {total:.0f} / 500")
    print(f"Average     : {average:.2f}")
    print(f"Percentage  : {percentage:.2f}%")
    print(f"Result      : {'PASS' if passed else 'FAIL'}")


if __name__ == "__main__":
    main()
```

**1. Run it:** `python grade_calculator.py`

**4. Codex's explanation of the important parts (summarised):**

- **`SUBJECTS` and `PASS_MARK`** are constants at the top, so subjects or the pass mark can be changed in one place.
- **`get_mark()`** uses a `while True` loop with `try/except ValueError` to catch text input, and an `if` check to reject marks outside 0–100. It only returns when the mark is valid.
- **`calculate()`** uses `sum()` for the total and divides by the number of subjects for the average. The percentage is total ÷ maximum marks × 100. `all()` checks that **every** subject is at least 40.
- **`main()`** collects marks using a list comprehension and prints the result in a neat format with 2 decimal places.
- **`if __name__ == "__main__":`** runs `main()` only when the file is run directly, not when it is imported (useful for testing).

**Step 4 – Implement.** Updated `task_manager.py`:

```python
from datetime import datetime, date

tasks = []


def add_task(title, due_date=None):
    if due_date:
        datetime.strptime(due_date, "%Y-%m-%d")  # raises ValueError if wrong format
    tasks.append({"title": title, "done": False, "due_date": due_date})


def complete_task(index):
    tasks[index]["done"] = True


def delete_task(index):
    tasks.pop(index)


def is_overdue(task, today=None):
    if not task["due_date"] or task["done"]:
        return False
    today = today or date.today()
    return datetime.strptime(task["due_date"], "%Y-%m-%d").date() < today


def list_tasks(today=None):
    lines = []
    for i, t in enumerate(tasks, start=1):
        status = "Done" if t["done"] else "Pending"
        due = t["due_date"] or "No due date"
        flag = "  <-- OVERDUE" if is_overdue(t, today) else ""
        lines.append(f"{i}. {t['title']} [{status}] Due: {due}{flag}")
    return lines
```

# Q3. Debug a Broken Application

*(Example application used for practice. The same workflow applies to the program given by the instructor.)*

**Workflow: Reproduce → Understand the Error → Find Root Cause → Implement Fix → Test → Check Side Effects**

**Original problem (`average_buggy.py`):** A program that calculates the average of student marks crashes for some inputs.

```python
def average(marks):
    total = 0
    for m in marks:
        total += m
    return total / len(marks)

print(average([80, 90, 70]))
print(average([]))
```

**1. Reproduce:** `python average_buggy.py`

**2. Error observed:**

```
80.0
Traceback (most recent call last):
  File "average_buggy.py", line 8, in <module>
    print(average([]))
  File "average_buggy.py", line 5, in average
    return total / len(marks)
ZeroDivisionError: division by zero
```

**3. Root cause identified by Codex:**
When the list is **empty**, `len(marks)` is **0**, and Python cannot divide by zero. The function never checks for an empty list. (This happens, for example, when a student has no marks entered yet.)

**4. Fix:**

```python
def average(marks):
    if not marks:          # handle empty list
        return 0
    return sum(marks) / len(marks)
```

(Codex also simplified the loop to `sum()`.)

**5. Test result:**

```
80.0
0
```

Normal input still gives 80.0, and an empty list now returns 0 instead of crashing.

**6. Side effects checked:**

- Normal lists give the **same result as before** (80.0). ✔
- Single-value list `[50]` → 50.0. ✔
- **One point to note:** returning `0` for "no marks" could be confused with a real average of 0. Codex suggested that, if needed, the function could return `None` and the caller could show "No marks available". No other functions were affected.

# Q4. Refactor and Test Existing Code

*(Example program used for practice. The same steps apply to the program given by the instructor.)*

**Original (poorly written) code – `report_old.py`:**

```python
def report(m1, m2, m3):
    if m1 >= 90:
        g1 = "A"
    elif m1 >= 75:
        g1 = "B"
    elif m1 >= 40:
        g1 = "C"
    else:
        g1 = "F"
    if m2 >= 90:
        g2 = "A"
    elif m2 >= 75:
        g2 = "B"
    elif m2 >= 40:
        g2 = "C"
    else:
        g2 = "F"
    if m3 >= 90:
        g3 = "A"
    elif m3 >= 75:
        g3 = "B"
    elif m3 >= 40:
        g3 = "C"
    else:
        g3 = "F"
    return [g1, g2, g3]
```

**1. Understanding (Codex):** The function takes 3 marks and converts each into a letter grade: A (≥90), B (≥75), C (≥40), F (<40). It returns a list of 3 grades.

**2. Problems found:**

- The **same grading logic is copied 3 times** (duplicated code).
- Unclear variable names (`m1`, `g1`…).
- It only works for exactly 3 subjects.
- If the grading rules change, they must be changed in 3 places, which can easily cause mistakes.

**3. Refactoring plan:**

1. Move the grading logic into one function, `get_grade(mark)`.
2. Make `report()` accept any number of marks.
3. Add docstrings.
4. Write tests to prove the behaviour is the same.

**4. Refactored code – `report_new.py`:**

```python
def get_grade(mark):
    """Return the letter grade for one mark."""
    if mark >= 90:
        return "A"
    if mark >= 75:
        return "B"
    if mark >= 40:
        return "C"
    return "F"


def report(*marks):
    """Return a list of grades, one for each mark."""
    return [get_grade(m) for m in marks]
```

**5. Tests for behaviour and edge cases – `test_report.py`:**

```python
import report_old, report_new


def test_grade_boundaries():
    assert report_new.get_grade(90) == "A"
    assert report_new.get_grade(89) == "B"
    assert report_new.get_grade(75) == "B"
    assert report_new.get_grade(74) == "C"
    assert report_new.get_grade(40) == "C"
    assert report_new.get_grade(39) == "F"
    assert report_new.get_grade(0) == "F"


def test_same_behaviour_as_old_code():
    for a in range(0, 101, 7):
        for b in (0, 39, 40, 75, 90, 100):
            assert report_new.report(a, b, 60) == report_old.report(a, b, 60)
```

**6. Run the tests:**

```
$ python -m pytest test_report.py -q
..                                                       [100%]
2 passed
```

**7. Behaviour unchanged?** **Yes.** The second test compares the old and new functions for many mark combinations, and they give exactly the same output. The boundary tests (39/40, 74/75, 89/90) confirm the grade limits did not change. The code is now shorter (from 25 lines to 12), easier to read, and has the grading rule in only one place.
